Sentinel — FCA Supervision Intelligence

An early-warning system for financial regulators. Sentinel mines the CFPB Consumer Complaint Database for AI- and automation-driven consumer harm, discovers the recurring patterns hiding in it, and ranks them so a supervisor can see what to act on first — balancing consumer protection against financial innovation.

I designed the backend behind the risk assistant. The core of it is a hybrid pipeline: a cheap deterministic model does the wide first pass, and the language model only adjudicates the ambiguous cases. That ordering is the whole point — it bounds hallucination risk to the small slice where judgement is genuinely needed, and keeps inference cost predictable instead of scaling with the size of the corpus. On top of that I built a human-in-the-loop mechanism that routes CRITICAL-severity complaints to a human regulator rather than letting the model close them.

For pattern discovery I chose unsupervised clustering over supervised classification. There is no ground truth for which harm pattern is this, and the goal was to surface patterns nobody had named yet — not to sort complaints into categories we had assumed in advance. Cluster count is chosen by silhouette score, and each pattern is ranked by a transparent weighted priority score over frequency, severity, growth and regulatory relevance.

Rent Right

Full-stack rental matching platform · AppWorks capstone

GitHub ↗

A rental platform that matches people to flats and to flatmates. Users get real-time notifications when a listing fits their criteria, and a compatibility score against potential roommates — built on a crawl-and-vectorise data pipeline running on AWS.

  • Roommate matching — a KDTree nearest-neighbour search over one-hot encoded lifestyle vectors (sleep schedule, cleanliness, noise tolerance) instead of a brute-force pairwise comparison.
  • Data pipeline — Selenium crawlers running on AWS Lambda extract listings, vectorise them, and load into MongoDB Atlas, with assets held in S3.
  • Infrastructure — three EC2 instances (Flask app, Redis, Celery) behind NGINX for availability, deployed through GitHub Actions.
  • Notifications — Celery background workers push personalised listings via the Line Notify API, so the request path never blocks on delivery.
  • Real-time chat — Socket.IO for instant messaging between matched roommates.
  • Observability — CloudWatch tracks EC2 metrics, Lambda invocations and login attempts, with automated email alerts.

Chat AI Backend

Real-time chat backend in Go

GitHub ↗

Less a chat app than an excuse to build a production-shaped Go service. The interesting work is underneath the feature list: a caching layer that keeps the database off the hot path, a shutdown sequence that does not drop in-flight messages, and an asynchronous log pipeline that survives a slow consumer.

  • Redis as a read layer in front of MongoDB — recent messages and sessions are served from cache, so database round-trips stay off the request path.
  • Graceful shutdown — in-flight messages are drained and persisted before the process exits, so a rolling deploy doesn't cost you a conversation.
  • Structured logging over Kafka — an asynchronous producer publishes JSON logs (level, timestamp, caller file and line) to a chatai-logs topic, with a dedicated goroutine draining the delivery-report channel so logging never blocks a handler.
  • OAuth 2.0 session management, served by Gin with Redis-backed auth middleware.
  • WebSocket transport for real-time message delivery, alongside a conversation CRUD API documented with Swagger.
  • Deployment — containerised with Docker Compose for local development, and shipped to GKE via Cloud Build.

Detecting Team Inefficiency in Hierarchical Multi-Agent RL

MSc dissertation · University of Bristol

GitHub ↗ code being prepared

When two reinforcement-learning agents cooperate, they can both look busy and still be wasting the team's time — one agent blocked in a corridor, the other assigned a subtask it cannot finish. This project defines that waste precisely enough to measure it, then penalises it during training.

  • Studies team-level inefficiency and high-level subtask allocation in hierarchical reinforcement learning, using Overcooked-AI as the cooperative multi-agent environment.
  • Separates frozen low-level subtask execution from a learned high-level allocation policy, so a failure can be attributed to the allocation rather than to execution — measured against a flat PPO baseline that maps observations straight to primitive actions.
  • Proposes a persistent-chain gap penalty: the high-level policy is penalised only when the same subtask is assigned consecutively, remains incomplete across multiple segments, and its execution gap exceeds a solo reference — three conditions, so ordinary slow progress isn't punished.
  • Calibrates persistence length and gap threshold using the future same-chain recovery rate, rather than hand-tuning them.
  • Defines a gap-analysis measurement for multi-agent systems, and evaluates across bottleneck and isolated layouts on soup performance, segment-level gap and persistent failure patterns.

Research question: does the selected joint high-level allocation create avoidable interaction loss, or fail to address an unambiguous team bottleneck?

STAG

Configurable multiplayer text-adventure engine · Java

GitHub ↗

A TCP client/server game engine that loads its entire world from data — locations and entities from Graphviz DOT files, actions from XML. New adventures can be authored without touching a line of engine code.

  • Three-stage command pipeline — CmdLexer identifies recognised verbs and entities, CmdParser validates and resolves ambiguity, then a built-in or dynamic handler applies the state transition.
  • Data-driven worlds — DOT for the map graph, XML for actions that consume and produce entities or unlock new routes.
  • Shared multiplayer state — one authoritative GameState with independent per-player location, inventory and health.
  • Robust parsing — case-insensitive input with punctuation and decorative words, plus explicit validation for ambiguous, incomplete and composite commands.
  • Built in Java 17 with OOP design patterns and SOLID principles; covered by unit and integration tests in JUnit 5.
